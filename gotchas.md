- VLCKit defaults to verbose logging that includes RTSP requests; `loggers = nil` alone is insufficient. Explicitly set verbosity to zero. Its snapshot API can raise Objective-C exceptions when video output disappears, so bridge that failure into an ordinary Swift error.
- VLCKit 3.7.3's wrapper uses asynchronous stop; its patched backend reports stopped before resource shutdown finishes. Serialize the public synchronous C stop off the main thread, preserving media observer lifetime. The relevant upstream patch is `libvlc/patches/0024-lib-media_player-add-stop-set_media-async-support.patch` in tag `3.7.3`.
- Snapshot creation synchronously waits up to 500 ms for a new frame and may report success without saving a file. Run it on the playback session's serial background queue, then check the output. Blocking the main thread here can prevent the frame from rendering. Use the backend's `isPlaying`, not VLCKit's last cached state, to monitor a healthy feed.
- For low-frame-rate cameras, wait for initial frame progress once, then retry a missed native snapshot within the original deadline. VLC source warns that its 500 ms snapshot wait is too short below 2 fps. Real 1 fps and warmed 0.25 fps captures exercise this path; controlled old-code runs also passed, so these tests do not prove a deterministic regression in the old retry gate.
- Capture attempts have a roughly 15-second deadline. Very sparse streams may take longer just to start decoding. The sparse capture test warms the real decoder first to separate startup from snapshot acquisition; it does not prove those cameras start within the app's deadline.
- Native computer control failed to start on this machine; actual XCTest UI automation still exercised the app. Keep screenshot attachments scoped to the popover to avoid capturing unrelated desktop content.
- Cold URL launch can deliver the link before launch completion, activation, and status-item layout. Tracing found an active app with a visible status-item window whose height was zero; `NSPopover.show` did nothing. A hot launch had height 39 and succeeded. Keep the request pending until activation and a nonempty visible anchor, then consume it only after a successful show. Activation alone is insufficient. Apple's `NSPopover.show(relativeTo:of:preferredEdge:)` documentation confirms invisible positioning views do not show popovers.

Test cleanup uses the system `security` command with the exact service and owned camera UUID; keep production credential permissions intact and preserve unrelated records.
